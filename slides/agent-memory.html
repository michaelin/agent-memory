Agent Memory

Persistent Knowledge for Coding Agents

github.com/michaelin/agent-memory

Welcome. This talk is about a problem every team using coding agents runs into eventually — agents that forget everything between sessions — and a principled system for fixing it.

We'll cover the problem, the memory experiment that shaped the design, the theory behind it, the system itself, and the Go tooling that makes it deterministic.

The Problem

Coding agents have no persistent memory and a limited, ephemeral context window.

Press ↓ for details

What an agent learns in one session dies when the session ends. Hard-won knowledge — patterns, constraints, decisions — evaporates.

Two problems compound each other: agents forget everything between sessions, and within a session the context window is both limited and unreliable as it fills up.

Two Distinct Failure Modes

Agent Amnesia

Knowledge is bounded by the session it was discovered in. Cross-project patterns, informal decisions, and hard-won observations are never recorded.

Context Rot

As the context window fills, LLMs become progressively less reliable at recalling earlier information. Loading everything makes things worse, not better.

Amnesia is about persistence across sessions. Context rot is about reliability within a session. Both need to be solved — and they require different solutions.

Solving Agent Amnesia

Out-of-repo Obsidian vault

Memory lives outside any single project. It survives repo deletion and spans codebases.

Atomic notes

One claim per note. Each fact can be individually verified, updated, or deprecated without touching anything else.

Write at task end

Agents are instructed to record durable findings at the end of every task — before the session closes.

The out-of-repo vault is the structural answer. Atomic notes keep it maintainable as it grows. The end-of-task write trigger is the behavioural answer — borrowed from Cline's Memory Bank pattern.

Solving Context Rot

Three memory tiers

Core is always loaded. Index is loaded at session start. Archival is fetched on demand only when a task requires it.

Hard token budgets

Core is capped at 600 tokens. Each index at 300. The majority of the context window stays free for actual work.

Search before load

Agents discover what exists via lightweight index files, then fetch only the specific note bodies they need.

The solution to context rot is not to load less — it is to load selectively. The three-tier architecture enforces this discipline mechanically. Agents cannot accidentally load more than they need.

Keeping Memory Sharp

Consolidate

End-of-task writes move discoveries from context into the vault before the session closes — short-term to long-term.

Curate

The Librarian scans for stale, contradicted, and unreviewed notes — pruning what no longer holds.

Confirm

Constraints and decisions require human sign-off before entering trusted memory. Agents cannot self-promote high-stakes facts.

Like sleep — the consolidation cycle is what keeps memory sharp over time.

The sleep analogy is deliberate. Sleep does two things: it consolidates short-term experience into long-term memory, and it prunes connections that are no longer useful. The consolidation cycle here does the same — write at task end (consolidate), Librarian runs hygiene (prune), human confirms high-stakes facts (validate). Without this cycle, memory only grows. It never sharpens.

The Memory Experiment

A shared, persistent memory layer — how it works, what we tried, and what was still missing

Press ↓ for details

A Shared, Persistent Memory Layer

An out-of-repo Obsidian vault that any agent — any framework, any role — can read and write. Knowledge is stored as atomic markdown notes with structured frontmatter. It survives repo deletion, spans projects, and is fully browsable by humans without any special tooling.

Out-of-repo

Lives outside any single project. Cross-project patterns are first-class citizens.

Atomic notes

One fact per file. Each claim can be verified, updated, or deprecated independently.

Agent-agnostic

Any framework on the same machine can use the same vault. No per-tool configuration.

The out-of-repo constraint is the most important structural decision. It means the memory is not tied to any project's lifecycle. The atomic note discipline is what makes the vault maintainable as it grows — you can deprecate one fact without touching anything else.

Three Moving Parts

Agents write

At the end of every task, agents deposit durable findings into the inbox — before the session closes.

Librarian consolidates

A dedicated agent runs the consolidation cycle — promoting, curating, and flagging what needs human review.

Humans confirm

Constraints and decisions require sign-off before entering trusted memory. The vault is always browsable in Obsidian.

The three-part split is deliberate. Agents are fast but unreliable curators — they write everything and let the Librarian sort it out. The Librarian is deterministic where possible and LLM-powered only where judgment is required. Humans are the final authority on high-stakes facts.

Every prior system makes memory possible. The consolidation cycle is what makes it stay sharp.

Basic Memory
Open-source MCP server (2.9k stars) that gives AI assistants persistent memory through Obsidian-compatible markdown files. The closest thing to what we built, but no governance layer.

MemGPT / Letta
Research project (now productized) that models agent memory explicitly with core, archival, and recall tiers. Rigorous theoretical model; wrong implementation for our use case.

Memory Bank (Cline)
A set of 6 structured markdown files at .memory/ that the agent reads at session start and updates after each session. Widely adopted; proves the autonomous write pattern works.

mem0
Open-source Python library providing a memory layer backed by vector search. Has automatic conflict detection via embedding similarity. Not human-readable without a separate UI.

Obsidian community
Practitioners using Obsidian as the sole memory store for AI agents, operating purely on the filesystem. Source of the _inbox/ staging area, _contested/ area, and append-only write patterns.

The gap
Every prior system makes persistent memory possible — agents can write, retrieve, and accumulate knowledge. None of them make it stay sharp. Without a consolidation cycle, memory degrades: stale beliefs accumulate, contradictions go unresolved, and future agents treat outdated facts as current truth. It is the difference between memory that grows and memory that ages gracefully.

Theoretical Foundations

Four ideas from different fields, composed together

Press ↓ for details

Epistemology

Not all knowledge is equal — how you know matters as much as what you know

Cognitive Science

The context window is working memory — load selectively, not exhaustively

Zettelkasten

Atomic, linked notes compound faster than long documents

Information Hygiene

Knowledge has a half-life — stale facts are worse than no facts

None of these four is sufficient alone. The design is the composition of all four. Each one explains a specific mechanism in the system.

Epistemology — Six Knowledge Types

TypeWhat it encodesTrust level
observationSomething directly read from the codebaseHigh — codebase is ground truth
patternA recurring theme inferred from 2+ observationsMedium — requires corroboration
constraintAn external rule the system must respectHigh — requires human confirmation
decisionA deliberate choice made by a humanAuthoritative — requires human confirmation
assumptionA belief held without verificationLow — must be re-verified before acting
synthesisA Librarian-derived summary across many notesDerived — not ground truth

Epistemic tagging tradition: Gwern.net · LessWrong · Devon Zuegel — governance layer is original

The governance rules — promotion path, human confirmation requirements — flow directly from these distinctions. The system encodes how you know what you know, not just what you know. Prior art on epistemic tagging: Gwern.net has used per-note certainty (impossible → certain) and importance tags since the early 2010s — one of the earliest systematic practitioners. The LessWrong community independently developed the "epistemic status: …" header convention around 2015–2018 as a community norm for flagging confidence before posts. Devon Zuegel extended this with both epistemic status and epistemic effort tags on her blog. What agent-memory adds is the governance layer: per-type promotion rules, human confirmation requirements, and TTL — none of which exist in those traditions.

Cognitive Science — Three Memory Tiers

Mirrors how human experts actually work — load selectively, not exhaustively

TierContentsWhen loadedBudget
Core Writing protocol, constraints summary, recent log tail Every session, unconditionally Under 600 tokens
Index Navigation files — titles and one-liners, no body content Session start, for current project and domains ~300 tokens each
Archival Full note bodies On demand, when a task requires them 10 bodies per query

The session starts lean and grows only as needed. Token budgets are sized to leave the majority of the context window free for actual work.

Memory tier model: MemGPT / Letta (2023) — token budgets and index tier are original

This is the critical discipline that prevents context rot. The index is the table of contents — you load it first, then open chapters only when you need them.

Zettelkasten + Information Hygiene

One note, one claim

Long documents under agent writes become 500-line blobs with contradicting claims. You can't deprecate a paragraph. You can deprecate a note. Wiki-links surface relationships; Obsidian makes the graph navigable.

Knowledge decays

A fact true in April may be false in October. Most memory systems ignore this. Every note carries a review-by date from birth. Deprecation never deletes — it links forward. The audit trail is preserved.

Luhmann's Zettelkasten (1960s–90s) established that knowledge compounds faster with atomic linked notes. The information hygiene principle is the least glamorous and the most important in practice.

System Design

Obsidian vault structure, write protocol, and the Librarian agent

Press ↓ for details

The tool owns the form. The agent owns the content.
Anything structural or rule-based lives in deterministic Go tooling. The agent's token budget is reserved for work only an LLM can do.

This is the single most important factoring rule. Every feature must pass the test: can this be done deterministically? If yes, it goes in a binary, not in an agent prompt.

Obsidian Vault Structure

Folder structure reflects lifecycle stage only. A note never moves after its first promotion — re-classification is a frontmatter edit, not a rename.

Folder structure reflects lifecycle stage only — not content type. Classification lives entirely in frontmatter. No rename operations after first promotion.

Note Format

One claim per note. Structured frontmatter for filtering; free-form markdown for the body.

--- title: "auth middleware runs before cors in server.go" type: observation status: inbox tags: [auth, middleware, golang] project: my-api source-artifact: internal/server/server.go --- # One short paragraph. One claim. ## Evidence — where this was observed ## Implications — what other agents need to know ## Related — [[wiki-links]] to connected notes
The agent never writes raw frontmatter. The write-note tool assembles it. The agent supplies the claim body, evidence, epistemic type, and confidence level — nothing else. Confidence is an explicit agent judgment: low, medium, or high. It defaults to medium if omitted. Wiki-links in the Related section must resolve to existing notes or promotion is blocked.

The Tool Owns the Form

Keep agent token budget for work only an LLM can do

Agent owns the content

  • Composing the claim — the body text
  • Picking the type when ambiguous
  • Assessing evidence quality and confidence
  • Deciding if two notes are the same claim
  • Drafting synthesis prose

Tool owns the form

  • Frontmatter assembly
  • Staleness scanning
  • Index regeneration
  • Inbox promotion
  • Search-before-write deduplication

Can this be done deterministically? If yes — it goes in the binary, not the prompt.

This principle is a key design decision in the system. LLM token budget is expensive and unreliable for mechanical tasks. Deterministic tooling is cheap, fast, and auditable. The split keeps agents focused on judgment and keeps the system predictable. The Go CLI (agent-memory) is the tooling layer — it runs as subcommands with JSON output, invoked by agents as tool calls or by the host outside any session.

Write Protocol

What the agent does vs. what the tool does

Agent's responsibility

Choose the epistemic type. Write the claim body and evidence. Declare the source artifact. Indicate whether this is a new claim, an update to an existing note, or a contradiction of one. That is all.

Tool's responsibility

Check for similar existing notes before writing. Assemble all frontmatter fields. Assign the staleness date. Run lint checks. Flag constraints and decisions for human review. Write to the inbox. Append to the log. The agent never writes raw frontmatter.

The similarity check is the key safety mechanism. If a similar note already exists and the agent hasn't made an explicit choice about it, the write is refused and the candidates are returned. The agent must decide: same claim, update, or genuine contradiction.

Knowledge Hygiene

The hard part — defending against six specific failure modes

Press ↓ for details

Most agent memory systems fail here. They write facts and never revisit them. The Obsidian vault gradually fills with outdated beliefs that future agents treat as current truth.

Knowledge poisoning compounds silently. By the time you notice, agents have been making decisions based on stale or wrong information for weeks.

Stale Facts

Something that was true in April is still in memory in October

Control: Every note carries a review-by date. A staleness scan at session start flags notes past their TTL before any work begins.

Assumption Poisoning

An agent writes a guess as a fact — future agents treat it as ground truth

Control: type: assumption is mandatory for unverified beliefs. Assumptions carry a 30-day TTL and must be re-verified before acting on them.

Conflicting Writes

Two agents write opposite conclusions — later agents pick whichever they find first

Control: Search-before-write — the tool checks for similar existing notes before accepting a new one. Near-duplicates are flagged rather than silently added.

Similarity is measured using Levenshtein distance on normalised note titles. Levenshtein distance counts the minimum number of single-character edits (insertions, deletions, substitutions) needed to turn one string into another — so "auth middleware order" and "auth middleware ordering" score as near-identical. Notes above the similarity threshold are surfaced to the agent before the write proceeds, so it can decide whether to update the existing note or add a genuinely distinct one.

Hallucination Laundering

An agent writes something it hallucinated — it gets retrieved as verified knowledge in future sessions

Control: All writes land in _inbox/ first. Constraints and decisions require explicit human confirmation before entering trusted memory.

Human confirmation is only required for constraint and decision notes — the two types where a wrong memory can silently shape agent behavior for months. For observations, the codebase is the ground truth: wrong memories fail fast.

Citation Collapse

A note loses track of where the claim came from — it becomes impossible to verify

Control: source-agent and source-artifact are mandatory fields. A note without a traceable origin cannot be promoted.

Silent Deprecation

A note is deleted or overwritten — the history of what was believed and when is lost

Control: Notes are never deleted. Superseded notes are deprecated with a forward link to the replacement — the audit trail is permanent.

The Tooling

A single Go binary — agent-memory — with subcommands

Agent-facing

context, write-note, search — the entire normal-operation surface

Maintenance

promote, reindex, tag, synthesize, curate

Lint

lint-note, lint-vault, backup — integrity gates

All subcommands support --json for machine-readable output. The agent-facing trio is the entire CLI interface a normal agent needs. The OpenCode plugin wraps these in registered tools so agents never need bash permissions.

The OpenCode plugin handles context injection, tool registration, and automatic promotion on session.idle — no agent definition changes required.

During work, agents search directly — reading the index files loaded at session start to discover what exists, then fetching specific note bodies as needed. There is no search command yet; the index is the navigation layer. The session-idle trigger is model-independent — promotion happens automatically without any agent needing to remember to call it.
